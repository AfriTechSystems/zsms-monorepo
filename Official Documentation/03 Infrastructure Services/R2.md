## Purpose

This document covers the complete Cloudflare R2 configuration for ZSMS — bucket structure, folder conventions, access patterns, signed URL generation, and upload handling. Every Claude Code session that reads or writes files must reference this document.

---

## Overview

ZSMS uses Cloudflare R2 for all file storage. R2 is S3-compatible object storage with no egress fees — unlike AWS S3, downloading files from R2 does not incur charges. This makes it cost-effective for high-volume PDF generation and download scenarios like bulk report cards.

Two buckets exist per country deployment. Files are never stored in the Supabase database — only the R2 path or signed URL is stored as a TEXT column.

---

## Bucket Structure

### Public Bucket — `zsms-public-zm`

Contains files that can be accessed via pre-signed URLs with moderate expiry windows. Not publicly accessible without a signed URL — "public" means accessible to authenticated ZSMS users, not the open internet.

```
zsms-public-zm/
├── {school_id}/
│   ├── branding/
│   │   └── logo.png                    School logo
│   ├── students/
│   │   └── {student_id}/
│   │       └── photo.jpg               Student profile photo
│   ├── reports/
│   │   └── {academic_year}/
│   │       └── term{N}/
│   │           └── {class_id}/
│   │               └── {student_id}.pdf  Report card PDF
│   ├── receipts/
│   │   └── {academic_year}/
│   │       └── term{N}/
│   │           └── {receipt_number}.pdf  Payment receipt PDF
│   ├── statements/
│   │   └── {student_id}_term{N}_{year}.pdf  Fee statement PDF
│   ├── templates/
│   │   └── {doc_type}_preview.pdf      Template preview PDFs
│   └── imports/
│       └── {import_job_id}/
│           └── error_report.xlsx       Import error report for download
```

### Private Bucket — `zsms-private-zm`

Contains sensitive documents that require short-expiry signed URLs. Extra access controls apply. Only Edge Functions with the service role key can write to this bucket.

```
zsms-private-zm/
├── {school_id}/
│   └── loan-proofs/
│       └── {loan_application_id}/
│           └── payslip.jpg             Loan application payslip upload
└── payment-proofs/
    └── {school_id}/
        └── {payment_id}/
            └── proof.jpg               Fee payment proof of payment
```

## Signed URL Generation

Files are never accessed directly via a public URL. Every file access goes through a signed URL generated by an Edge Function. This ensures:
- RLS-equivalent access control at the file level
- Short expiry windows limit exposure if a URL is shared
- All file access is traceable through the Edge Function that generated the URL

### Signed URL Expiry by File Type

| File Type | Expiry | Reason |
|---|---|---|
| School logo | 24 hours | Frequently displayed, low sensitivity |
| Student photo | 1 hour | Personal data — short window |
| Report card PDF | 30 days | Parents share with family, need time to download |
| Payment receipt PDF | 7 days | Administrative use |
| Fee statement PDF | 7 days | Administrative use |
| Loan payslip | 15 minutes | Highest sensitivity — minimum exposure |
| Payment proof | 1 hour | Accountant review window |
| Import error report | 2 hours | Admin downloads and discards |

### Generating a Signed URL in an Edge Function

```typescript
import { S3Client, GetObjectCommand } from 'https://esm.sh/@aws-sdk/client-s3@3'
import { getSignedUrl } from 'https://esm.sh/@aws-sdk/s3-request-presigner@3'

const r2 = new S3Client({
  region: 'auto',
  endpoint: `https://${Deno.env.get('CLOUDFLARE_R2_ACCOUNT_ID')}.r2.cloudflarestorage.com`,
  credentials: {
    accessKeyId: Deno.env.get('CLOUDFLARE_R2_ACCESS_KEY_ID')!,
    secretAccessKey: Deno.env.get('CLOUDFLARE_R2_SECRET_ACCESS_KEY')!,
  },
})

async function getSignedDownloadUrl(
  bucket: string,
  key: string,
  expirySeconds: number
): Promise<string> {
  const command = new GetObjectCommand({ Bucket: bucket, Key: key })
  return getSignedUrl(r2, command, { expiresIn: expirySeconds })
}

// Usage
const reportCardUrl = await getSignedDownloadUrl(
  Deno.env.get('CLOUDFLARE_R2_PUBLIC_BUCKET')!,
  `${schoolId}/reports/${year}/term${term}/${classId}/${studentId}.pdf`,
  60 * 60 * 24 * 30  // 30 days
)
```

## File Upload Patterns

### Image Upload (Student Photos, School Logos, Payment Proofs)

Images are compressed before upload. The compression target is under 200KB for student photos and under 500KB for payment proofs. This keeps storage costs low and ensures PDFs containing student photos render quickly.

```typescript
async function uploadImage(
  file: File,
  bucket: string,
  key: string
): Promise<string> {
  // Compress image client-side before upload
  const compressed = await compressImage(file, { maxSizeKB: 200, quality: 0.8 })

  const { PutObjectCommand } = await import('https://esm.sh/@aws-sdk/client-s3@3')

  await r2.send(new PutObjectCommand({
    Bucket: bucket,
    Key: key,
    Body: await compressed.arrayBuffer(),
    ContentType: compressed.type,
    Metadata: {
      'uploaded-by': userId,
      'school-id': schoolId,
      'upload-timestamp': new Date().toISOString(),
    },
  }))

  return key  // Store the key in the database, not a full URL
}
```

### PDF Upload (Generated Report Cards, Receipts)

PDFs are generated in Edge Functions and uploaded directly from the server — no client-side upload involved.

```typescript
async function uploadPDF(
  pdfBuffer: Uint8Array,
  bucket: string,
  key: string
): Promise<string> {
  await r2.send(new PutObjectCommand({
    Bucket: bucket,
    Key: key,
    Body: pdfBuffer,
    ContentType: 'application/pdf',
    Metadata: {
      'generated-at': new Date().toISOString(),
      'school-id': schoolId,
    },
  }))

  return key
}
```

### Client-Side Upload Flow (Payment Proofs, Payslips)

For files uploaded by users (payment proofs, loan payslips), the client never uploads directly to R2. Instead:

1. Client requests a pre-signed upload URL from an API route
2. API route validates permissions and generates a PUT signed URL (valid 5 minutes)
3. Client uploads directly to R2 using the signed URL
4. Client confirms upload to the API route
5. API route records the R2 key in the database

```typescript
// API route — generate upload URL
const uploadUrl = await getSignedUrl(r2, new PutObjectCommand({
  Bucket: bucket,
  Key: key,
  ContentType: allowedMimeType,
  ContentLength: fileSize,  // Enforce file size limit server-side
}), { expiresIn: 300 })  // 5-minute upload window

return { uploadUrl, key }
```

This pattern means R2 credentials never reach the client browser or mobile app.

## File Naming Conventions

All file keys follow the folder structure defined in the bucket layout above. Specific rules:

- School ID always first: `{school_id}/...`
- Use the database UUID or record ID for uniqueness — never filenames provided by users
- File extensions are always lowercase: `.pdf`, `.jpg`, `.png`
- No spaces or special characters in keys — use hyphens for readability
- Timestamps in filenames use ISO format without colons: `2026-09-15T102300`

```
✅ ZM-LSK-0001/reports/2026/term2/grade7a/550e8400-e29b-41d4-a716.pdf
✅ ZM-LSK-0001/students/STU-ZM-LSK-0001-00042/photo.jpg
✅ ZM-LSK-0001/receipts/2026/term2/REC-ZM-LSK-0001-000001.pdf

❌ ZM-LSK-0001/report cards/term 2/Chanda Bwalya report.pdf
❌ ZM-LSK-0001/students/chanda photo upload 15-09-2026.jpeg
```

## Storage Cost Management

R2 pricing: $0.015 per GB stored per month. No egress fees.

At 100 schools with 500 students each generating 3 report cards per year (one per term):
- 150,000 report card PDFs per year
- Average PDF size: 150KB
- Total storage: ~22.5 GB
- Monthly cost: ~$0.34

Storage costs are negligible at pilot scale. Monitor monthly storage growth in the Cloudflare dashboard as the school count grows.

**Retention policy (future):** Report cards older than 7 years can be archived to Cloudflare's cheaper storage tier. Implement when storage costs become meaningful — not in Phase 1.

## Backup Strategy

Critical database backups are exported daily to R2 as a secondary storage location (Supabase performs its own point-in-time recovery — this is an additional safety layer):

```
zsms-public-zm/
└── _backups/
    └── {date}/
        └── schema_backup.sql
```

This backup is written by a daily queue cron job that runs at 02:00 UTC. It is never accessible via signed URL — it is a cold backup for disaster recovery only.

## Business Rules

1. Files are never stored in the Supabase database. Only the R2 key (path string) is stored in database columns.
2. Loan payslips and payment proofs are always stored in the private bucket with 15-minute and 1-hour signed URL expiry respectively.
3. Client-side code never has direct R2 credentials. All uploads use server-generated pre-signed PUT URLs.
4. File size limits are enforced server-side when generating upload URLs: photos max 5MB, PDFs not applicable (generated server-side), payment proofs max 10MB.
5. File types are validated server-side: photos accept `image/jpeg` and `image/png` only. Payment proofs accept `image/jpeg`, `image/png`, and `application/pdf` only.
6. Files are never deleted from R2 — they are soft-referenced. If a student is deleted from the database, their R2 files remain until the scheduled retention cleanup runs.

## Known Limitations and Future Work

- R2 does not support server-side image transformation (resizing, format conversion). Client-side compression is used instead. Future: Cloudflare Images can be added for automatic resizing and WebP conversion.
- The private bucket does not have automatic expiry (lifecycle rules for loan payslips after 7 years). This will be configured as a Cloudflare R2 lifecycle rule when the loan module launches.
- Cross-country file access (e.g. an AfriTech super admin viewing a file from any country) requires knowing which country bucket to query. The school_id prefix makes this deterministic — the country code in the school_id identifies the bucket.
